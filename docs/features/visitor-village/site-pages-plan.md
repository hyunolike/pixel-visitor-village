# 홈·설치·사용 문서 개편 계획

사용자가 레퍼런스 비교 뒤 제안한 3페이지 구성의 실행을 승인했다. 현재 HEAD 0fcdb54, 기존 feat/visitor-notice 작업 공간을 이어 사용한다. 이번 승인은 구현/검증이며 새 커밋/푸시/공개 배포는 포함하지 않는다.

## 확정 범위

- 홈 `/`: 한 문장 설명 → 실제 24명 시연과 기존 계절/인원/빛/정지 제어 → 기능 소개 → 기존 영상 → 설치 3단계 → FAQ → 문서/GitHub/출처. 첫 행동은 설치, 보조 행동은 데모 이동이다. 24명은 시연임을 명시하고 오늘 누적 집계와 동시 접속자를 구분한다.
- 설치 `/install.html` 및 기존 Pages `/install`: 기존 4개 언어/설정/dirty/복사/모바일 행동/미리보기를 보존하고 홈/설치/문서/GitHub 내비게이션과 설치 후 확인 도움말을 추가한다. 문서 링크는 다른 언어에서 한국어 문서임을 표시한다.
- 문서 `/docs/`: `docs/index.html`을 Vite 다중 HTML 진입점에 추가한다. 빠른 시작, 5개 속성 표, 오늘 집계/선택적 확인의 경계, 문제 해결, 개발/자체 호스팅과 에셋 출처를 정적 한국어 HTML로 제공한다. 제목/본문/앵커는 JS가 꺼져도 읽힌다. 기존 Markdown 설계/검토 문서는 빌드 출력에 복사하지 않는다.
- 홈/문서는 기존 한국어를 유지하며 설치의 4개 언어를 확대/축소하지 않는다. 신규 로그인/수집/API/설치 확인 서버와 신규 에셋/의존성은 추가하지 않는다.

## 시각 방향과 경로

기존 토큰과 각진 컨트롤을 재사용한다. 홈은 기존 숲색(#0f1d20/#162426)과 밝은 본문(#eef0f4), 라벤더 행동색(#c2bdff), 문서는 기존 밝은 바탕(#f7f8fc/#fff)과 본문(#242638), 행동색(#5752cf)을 사용한다. 글자와 브랜드는 기존 --font-ui와 역할 크기를 따른다. 기억에 남는 중심은 실제 움직이는 마을이며 추가 장식/등장 애니메이션은 넣지 않는다.

홈: [브랜드 | 체험 설치 문서 GitHub] / [설명 + 설치 버튼] / [마을 + 기존 제어] / [기능 3개] / [영상] / [설치 순서] / [FAQ + 출처]. 문서: [같은 브랜드/메뉴] / [제목] / [목차 | 본문]으로 넓은 화면은 두 열, 작은 화면은 목차를 본문 위에 둔다. 320px에서 줄바꿈하며 코드/표만 내부 스크롤한다.

사이트 경로는 기존 상대 링크 정책을 유지한다. 홈과 설치에서 `./docs/`, 문서에서 `../index.html#demo`, `../install.html`을 사용한다. `#demo`, `#intro-film`과 기존 폼/위젯 ID를 보존한다. 문서의 `#quick-start`, `#configuration`, `#visitor-count`, `#troubleshooting`, `#development`, `#credits`를 공개한다. `/install`의 서버 별칭은 기존 Pages 동작이며 로컬 검사는 `/install.html`을 사용한다.

## 구현 단계

1. tests/widget.spec.ts에 홈 설명→데모/설치→문서→설치 흐름, 목차 앵커, JS 비활성 문서, 320px, 네 언어 문서 메뉴와 기존 코드 생성 보존 검사를 추가한다. 기존 번들에서 실패를 먼저 확인한다.
2. src/demo.ts/demo.css와 신규 src/site-pages.css: 홈 내용과 공통 내비게이션/문서 레이아웃을 구현한다. 기존 위젯 생성은 한 번만 하며 모델/렌더러/영상 동작을 바꾸지 않는다.
3. docs/index.html과 vite.config.ts: 정적 문서와 빌드 진입점. 옵션의 기본값/범위와 paused boolean 계약은 실제 모델/README에 맞춘다. 시각·지역 수집이 없고 1분 확인이 개별 방문 이벤트가 아님을 명시한다.
4. install.html과 src/install-i18n.ts/install.css: 네 언어의 docsLink/installLink/checkDocs 문구를 추가하고 헤더/안내에 연결한다. src/install.ts의 기존 data-i18n 갱신 경로를 사용한다. 언어 전환은 입력/코드/dirty/포커스를 유지한다.
5. 네 언어 README에 실제 사용자 문서 진입점을 연결한다. spec/design/tasks와 실제 검토 기록을 갱신한다. pnpm test/typecheck/build/test:e2e와 실제 데스크톱/320px 캡처를 확인한다. 독립 코드 검토의 중요 지적을 수정하고 검증한다.

## 검토 초점

- 긴 홈으로 바뀌어도 기존 offscreen/영상/위젯 제어 검사가 실제 보이는 상태를 기다리는지.
- 문서 깊이에서 CSS/홈/설치/이미지 경로가 깨지지 않고 HTML만으로 내용을 읽을 수 있는지.
- 설치 메뉴가 좁은 화면/4개 언어에서 가로 넘침이나 기존 하단 행동의 가림을 만들지 않는지.
- 오늘 집계를 실시간 동시 접속/개별 방문자의 신원으로 설명하지 않는지. 자정/캐시/선택 조회의 한계를 안내하는지.
- 문서 링크와 사이트 메뉴 추가가 기존 키보드/코드 생성/언어 전환 상태를 바꾸지 않는지.
