# 방문자 픽셀 위젯 요구사항

상태: 초안. 저장소 준비만 요청받았으며 제품 설계는 아직 승인되지 않았다.

## 목적과 첫 사용 가치

블로그 운영자가 방문자 수를 살아 있는 픽셀 풍경으로 표현한다. 독자는 블로그를 열었을 때 오늘의 방문 규모에 따라 캐릭터들이 돌아다니는 모습을 본다.

첫 흐름: 운영자가 스킨에 위젯을 삽입한다 → 독자가 페이지를 연다 → 오늘 방문자 수에 해당하는 캐릭터가 생성되어 움직인다.

## 요청에서 확인한 내용

| ID | 요구사항 | 관찰 가능한 수용 기준 |
| --- | --- | --- |
| VV-001 | 티스토리 웹 화면에 삽입할 수 있다. | 실제 대상 스킨에서 설치 후 위젯이 표시된다. |
| VV-002 | 오늘 방문자 수만큼 캐릭터가 생성된다. | 입력 0, 1, 37일 때 각각 0, 1, 37개의 캐릭터가 존재한다. 시연 숫자는 실제 집계로 표시하지 않는다. |
| VV-003 | 귀여운 픽셀 캐릭터가 스스로 움직인다. | 사용자 조작 없이 걷기와 멈추기를 반복하며 정해진 활동 영역을 벗어나지 않는다. |
| VV-004 | iframe 외의 삽입 기술을 검토한다. | 설계에 Web Components 방식과 대안, 티스토리 연결 방법이 기록된다. |

## 구현 전 확정할 제안

- 첫 버전은 페이지를 열었을 때의 오늘 방문자 수를 사용한다. 열린 페이지에 새 방문을 실시간 반영하는 기능은 후속 범위로 둔다.
- 잘못된 숫자는 임의의 방문자 수로 바꾸지 않고 안내하거나 위젯만 표시하지 않는다. 블로그 본문은 정상적으로 사용할 수 있어야 한다.
- 모션 줄이기를 요청한 환경에서는 자동 이동을 줄이거나 정지한다.
- 방문자가 많아도 입력 수를 조용히 잘라 내지 않는다. 표시 수 제한이나 화면 밖 관리가 필요하면 표시 정책을 먼저 합의한다.

## 미정 사항

1. 활동 영역: 작은 마을 상자, 블로그 하단 또는 페이지 여백.
2. 캐릭터 종류와 픽셀 크기, 걷기와 쉬기 동작의 시각적 스타일.
3. 예상 최대 일일 방문자 수와 저사양 기기에서의 표시 정책.
4. 대상 블로그 주소와 스킨, 모바일 스킨 적용 범위.

## 현재 범위 밖

동시 접속자 표시, 방문자 신원 추적, 채팅, 멀티플레이, 캐릭터 계정, 유료 서비스와 게임 캐릭터 에셋 재사용.

## 검증 계획

구현 후 숫자 입력과 이동 경계의 단위 테스트, 작은 화면과 모션 줄이기 검증, 실제 티스토리 스킨 설치를 확인한다. 방문자 규모에 따른 성능 목표는 예상 최대 수를 확인한 뒤 정한다.
