## 2026-11-24 설치 페이지 개편과 다국어 — 구현 승인

사용자는 외부 레퍼런스를 참고한 새 디자인 시스템과 설치 페이지 개편 및 다국어 처리를 요청했고, 시각 보드와 아래 네 언어 범위를 확인한 뒤 “진행해줘”로 구현을 승인했다. 기존 요구사항은 아래에 유지한다.

| ID | 요구사항 | 수용 기준 |
| --- | --- | --- |
| VV-INSTALL-001 | 설치 화면에 재사용 가능한 디자인 시스템을 적용한다. | 색상/글자/간격/컴포넌트 상태가 문서와 CSS 토큰에 대응한다. 320px 이상에서 페이지 가로 넘침이 없다. |
| VV-INSTALL-002 | 선택 계절을 설치 전에 확인한다. | 기존 위젯으로 5개 계절을 미리 본다. 24명은 시연용임을 명시한다. 미리보기 실패에도 코드 생성이 가능하다. |
| VV-INSTALL-003 | 설치 화면을 한국어, 영어, 일본어와 중국어 간체로 제공한다. | 문서 lang/title, 폼, 계절명, 오류, 복사 상태, 설치 안내와 접근성 문구가 전환된다. 언어 전환 시 주소/계절/코드/포커스를 유지한다. |
| VV-INSTALL-004 | 언어 결정과 오류 복구가 예측 가능하다. | URL → 저장 선택 → 브라우저 → 한국어 순이며 잘못된 언어와 저장소 실패를 처리한다. 오류와 결과는 보조 기술에 전달한다. |

현재 호스트의 위젯 주소, 티스토리 치환자, URL 검증과 직접 스킨에 붙여 넣는 계약을 유지한다. 외국어 안내에서도 티스토리 실제 메뉴명은 한국어 원문을 함께 제공한다. 미리보기 위젯 UI는 선택 언어를 따르고 외부 삽입 위젯의 기본 한국어 계약은 유지한다. 메인 데모 전체 개편/번역, 커밋/푸시/배포와 실제 스킨 쓰기는 별도 범위다.

상태: 초안. 픽셀 방문자 마을에 더해 중앙의 큰 나무와 계절별 꾸미기, 현재 크리스마스 장식을 요청받았다. 2026-11-20 미리보기 확인 후 구현 승인을 받았다.

## 목적과 첫 사용 가치

블로그 운영자가 방문자 수를 살아 있는 픽셀 풍경으로 표현한다. 독자는 블로그를 열었을 때 오늘의 방문 규모에 따라 캐릭터들이 돌아다니는 모습을 본다.

첫 흐름: 운영자가 스킨에 위젯을 삽입한다 → 독자가 페이지를 연다 → 오늘 방문자 수에 해당하는 캐릭터가 생성되어 움직인다.

## 구현 전 확정할 제안

- 첫 버전은 페이지를 열었을 때의 오늘 방문자 수를 사용한다. 열린 페이지에 새 방문을 실시간 반영하는 기능은 후속 범위로 둔다.
- 잘못된 숫자는 임의의 방문자 수로 바꾸지 않고 안내하거나 위젯만 표시하지 않는다. 블로그 본문은 정상적으로 사용할 수 있어야 한다.
- 모션 줄이기를 요청한 환경에서는 자동 이동을 줄이거나 정지한다.
- 방문자가 많아도 입력 수를 조용히 잘라 내지 않는다. 표시 수 제한이나 화면 밖 관리가 필요하면 표시 정책을 먼저 합의한다.

- 계절 변경은 운영자가 테마 설정으로 선택하는 방식을 우선 제안한다. 자동 날짜 전환과 장식을 드래그하는 편집기는 별도 범위로 둔다.

## 미정 사항

1. 중앙 나무를 담을 마을 영역의 크기와 블로그 내 설치 위치. 중앙 나무 배치는 사용자 요청으로 확정했다.
2. 캐릭터 종류와 픽셀 크기, 걷기와 쉬기 동작의 시각적 스타일.
3. 예상 최대 일일 방문자 수와 저사양 기기에서의 표시 정책.
4. 대상 블로그 주소와 스킨, 모바일 스킨 적용 범위.

## 현재 범위 밖

동시 접속자 표시, 방문자 신원 추적, 채팅, 멀티플레이, 캐릭터 계정, 유료 서비스와 게임 캐릭터 에셋 재사용.

## 검증 계획

구현 후 숫자 입력과 이동 경계의 단위 테스트, 작은 화면과 모션 줄이기 검증, 실제 티스토리 스킨 설치를 확인한다. 방문자 규모에 따른 성능 목표는 예상 최대 수를 확인한 뒤 정한다.

## 승인 후 구체화한 첫 버전 범위

계절은 운영자가 직접 선택한다. 동작 가능한 독립 마을 영역과 5개 계절 외형을 만든다. 안전 한도는 5,000명이며 초과 입력은 오류로 안내하고 절삭하지 않는다. 다른 계절 그림은 자체 제작한 픽셀 외형이고 크리스마스는 생성 PNG다. 실제 티스토리 계정/스킨 접근이 없어 설치 예제와 배포 번들까지 검증하고 실제 스킨 연결은 후속으로 남긴다.

## 배포 준비 범위

2026-11-20 사용자가 대화 미리보기 표시 문제를 보류하고 진행을 요청했다. 정적 배포 설정, 외부 블로그의 ES 모듈 로드와 설치 코드, 배포 묶음을 준비한다. 실제 블로그 주소와 공개 배포 여부를 확인 중이며 공개 업로드나 스킨 쓰기를 자동 승인으로 간주하지 않는다.

## 주소 입력 설치 도우미

사용자가 Vercel 공개 배포를 요청했고 티스토리 주소만으로 적용할 수 있는지 질문했다. 설치 도우미는 주소 검증 → 실제 배포 주소가 들어간 코드 생성/복사 → 해당 블로그 관리자 링크로 이동하는 흐름을 제공한다. 스킨은 소유자가 최초 한 번 직접 수정한다. 주소만으로 설치되었다고 표시하지 않는다. 계정 비밀번호와 인증키는 받지 않는다.

## 2026-11-20 캐릭터 외형 개선

사용자가 관련 레퍼런스를 검색한 뒤 픽셀 캐릭터 개선을 진행하도록 요청했다. 기존 VV-003의 귀여운 캐릭터와 자율 이동을 구체화한다.

- VV-007: 20×28px 원본에 얼굴, 머리 모양, 옷과 소품이 구분되는 자체 제작 캐릭터 8종을 제공한다. 마을의 픽셀 배율을 유지한다.
- VV-008: 앞, 뒤, 옆 방향과 좌우 반전, 걷기 4프레임, 정지 자세와 눈 깜박임을 제공한다. 모델의 실제 걷기/쉬기 상태와 방향이 화면에 일치해야 한다.
- VV-009: 스프라이트는 위젯당 하나의 공유 아틀라스로 만들고 방문자 수에 따라 다시 생성하지 않는다. 제거 시 공유 GPU 소스를 한 번 해제한다.
- 방문자 수, 위치, 줄기 충돌, 계절 선택, 모션 줄이기와 공개 컴포넌트 계약을 유지한다.
- 외부 작가의 이미지나 게임 캐릭터는 배포에 포함하지 않는다. 레퍼런스는 비율, 가독성과 동작 제작 방법에만 사용한다.

수용 확인: 동작 선택 단위 테스트, 8종×3방향×6자세의 픽셀 프레임 검사, 실제 Chrome에서 마을/확대 시트 확인, 기존 5,000명·계절·재연결·모션 줄이기 브라우저 검사.

## 2026-11-20 소개 영상과 썸네일

사용자가 Claude Code에서 brag 스킬을 사용해 썸네일과 바로 재생할 수 있는 소개 영상을 추가하도록 요청했다. 구현은 `feat/brag-intro`, 기준 `a9c5ff5`에서 진행한다.

- VV-010: 실제 제품의 마을과 캐릭터가 움직이는 약 20초의 한국어 소개 영상, 가장 잘 읽히는 장면의 썸네일과 README용 자동 움직임 미리보기를 제공한다. 제작은 실제 Claude Code의 brag 스킬로 수행하고 사용 출처를 기록한다.
- VV-011: 데모 안에 음소거 자동 재생과 반복, 인라인 재생, 기본 재생/소리 조절, 포스터와 영상 파일 링크를 제공한다. README의 움직임 미리보기에서 해당 영상 영역으로 이동할 수 있다.
- VV-012: 모션 줄이기 설정에서는 자동 재생하지 않으며 사용자가 직접 재생할 수 있다. 화면 밖과 숨긴 탭에서는 재생을 중지하고, 자동 중지 이전에 재생 중이었을 때만 다시 보이면 재개한다. 사용자의 일시 정지를 자동으로 취소하지 않는다.
- 영상이 로드되지 않으면 썸네일과 오류 안내, 영상 파일 링크를 남긴다. 작은 화면에서 가로 넘침 없이 사용할 수 있어야 한다.
- 실제 티스토리 집계/설치, 동시 접속자와 원격 자동 설치를 영상의 검증된 기능으로 주장하지 않는다. 영상 속 방문자 수는 시연용이다.

사용 위치 선호를 비동기 질문으로 확인했고, 답변 전에는 추천 기본값인 README와 데모 양쪽으로 구현했다. 영상 생성은 이 선택과 독립적으로 진행했다. 커밋과 외부 공개는 후속 요청에서 진행한다.

## 2026-11-20 마을 환경 에셋 개선

사용자는 계절별 마을의 기존 README 화면을 첨부하고 캐릭터 이외 주변 마을 에셋 개선을 요청했다.

- VV-013: 집, 지붕, 창문/문, 돌길, 가로등, 울타리, 숲과 작은 거리 소품의 픽셀 디테일을 높인다. 기존 캐릭터의 외형과 이동/수/계절 계약을 유지한다.
- VV-014: 중앙 사계절 나무를 층과 명암이 있는 둥근 수관, 꽃/잎/단풍, 겨울 가지와 눈으로 구분한다. 기존 크리스마스 PNG는 유지한다. 주변 장식도 계절에 따라 꽃/초록 식생/낙엽과 호박/눈으로 달라진다.
- VV-015: 고정 소품은 발 기준 깊이로 캐릭터와 함께 정렬한다. 집 뒤로 걸으면 집에 가려지고 앞으로 걸으면 앞에 보인다. 환경은 테마/크기 변경 때만 만들고 매 프레임 다시 그리거나 방문자 수에 따라 재생성하지 않는다.
- 좁은 화면은 필수 집과 가로등을 우선 배치하고 추가 작은 집/벤치/표지판을 줄인다. 아주 작거나 0인 호스트 크기에서도 유효한 양수 캔버스를 만든다. 중앙 줄기와 진입로를 고정 소품으로 막지 않는다.
- 외부 게임 에셋과 새 런타임 의존성을 추가하지 않는다. 기존 Canvas 코드 기반 에셋을 직접 그린다. 새 장애물/상호작용이나 캐릭터 이동 모델 변경은 이번 범위 밖이다.

수용 확인: 반응형 소품 배치 단위 검사, 모든 계절의 실제 마을과 소품 확대 시트 확인, 320px/작은 높이/재연결/계절 및 위치 보존/5,000명 기존 브라우저 검사. README의 계절별 그림을 개선 버전으로 갱신한다. 기존 소개 영상은 이전 제품 버전의 고정 렌더로 유지한다.

## 2026-11-21 Cloudflare Pages 이전

사용자는 Vercel 이외 무료 플랜 비교 뒤 Cloudflare Pages로 진행하도록 요청했다. 기존 공개 Vercel 주소는 402/DEPLOYMENT_DISABLED로 응답하며 PR #5까지 병합된 기준 커밋은 `234e854`다.

- VV-016: 무료 Pages 프로젝트에 최신 데모, 설치 도우미, 독립 위젯과 소개 영상을 공개 정적 파일로 제공한다. 계정 로그인은 사용자 OAuth로 수행하며 유료 플랜/도메인/Functions/DB를 만들지 않는다.
- VV-017: `/widget/visitor-village.js`는 실제 HTTPS에서 JavaScript MIME, `Access-Control-Allow-Origin: *`, 5분 캐시와 재검증, `nosniff`를 제공한다. 없는 파일은 HTML 성공 응답으로 위장하지 않고 404다.
- VV-018: 설치 도우미는 실제 Pages origin으로 코드를 만들고 README와 스킨 예제는 확인된 공개 주소를 가리킨다. 임시/후보 주소를 실제 배포 주소로 기록하지 않는다. 기존의 시연 숫자/실제 티스토리 구분을 유지한다.
- 기존 캐릭터/마을/영상/공개 API와 0~5,000명 계약을 유지한다. 기존 Vercel 프로젝트와 설정은 삭제하지 않는다. 커밋/푸시/새 PR과 GitHub 자동 배포는 이번 요청에 포함하지 않는다.

수용 확인: 단위/타입/빌드와 기존 브라우저 회귀, Pages 로컬 런타임의 헤더/라우팅, 실제 비로그인 HTTPS에서 위젯 해시/CORS와 별도 출처 삽입, 설치 코드의 origin과 5개 테마/모바일/영상 재생을 확인한다. Range 지원은 실제 응답대로 기록하며 206을 가정하지 않는다. 실제 스킨과 모바일 실기기는 별도 확인이다.


## 2026-11-24 방문 수 팻말과 저장소 링크

사용자가 실제 블로그 화면과 URL을 제공하고 조사 후 진행을 승인했다.

- VV-019: 작은 자체 제작 나무 팻말로 첫 오늘 방문 수와 같은 한국 날짜의 증가분을 알린다. 동일 값/감소/날짜 변경을 새 방문으로 오인하지 않는다. 화면 밖 중지와 모션 줄이기를 지원한다.
- VV-020: 마을 전체 클릭과 키보드 링크 활성화로 프로젝트 저장소를 새 탭에서 연다. 목적지를 표시하고 모바일 스크롤을 유지한다.
- VV-021: 명시적으로 켠 경우 60초 이상 간격으로 같은 블로그 HTML의 오늘 방문 수를 확인한다. 중복/중첩 요청과 숨김 상태의 요청을 막으며 실패 시 마지막 상태를 보존한다. 티스토리 공식 실시간 스트림으로 설명하지 않는다.

상세 수용 조건과 파일별 실행 순서는 [방문 수 팻말 계획](visitor-notice-plan.md)에 있다. 반복 조회의 실제 집계 영향은 미검증이므로 기본으로 켜지 않는다.
