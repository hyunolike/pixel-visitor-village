# 방문 수 팻말과 저장소 링크 검토

기준: 24010fc에서 시작한 feat/visitor-notice의 미커밋 변경. 방문 수 알림과 선택적 확인, 저장소 링크만 검토했다. 같은 작업 공간의 설치 페이지 재설계 제안 문서는 별도 작업으로 보존했다.

## 사전 설계 검토

실제 새 문맥의 notice_spec_review가 EGM implementation_readiness persona와 implementation-readiness standard, 실행 계획, 관련 소스/테스트를 읽었다. 발견한 중요 항목 네 개를 계획에 반영했다.

1. 활성 구독자의 최소 간격과 전달 대상, 실패 백오프/복구 규칙 확정.
2. 조회 중 외부 count 변경 및 구독 활성 세대 변경 시 응답 무효화.
3. HTML 내 복수 위젯의 값이 모두 유효하고 같을 때만 적용.
4. 오류 안내와 팻말 live region 분리, 숨김 중 증가/감소와 재표시 기준 확정.

## 구현 후 독립 코드 검토

실제 새 문맥의 notice_code_review가 요청한 코드 검토 계약에 따라 관련 변경과 새 모듈을 읽기 전용으로 검토했다. 다른 하위 검토자를 만들지 않았고 서버/브라우저 검사는 실행하지 않았다. Critical과 Minor는 없었고 Important 네 건을 보고했다. 아래 수정 후 별도 재검토를 수행했다고 주장하지 않으며, 해당 회귀 테스트의 실패와 수정 후 전체 통과로 조치 확인했다.

| 발견 | 실패 재현 | 수정 |
| --- | --- | --- |
| 최초 잘못된 치환자에서 정상 0으로 바뀌면 첫 팻말이 없음 | genuine zero 브라우저 검사에서 빈 문구 재현 | 아직 정상 안내를 하지 않은 경우 같은 숫자도 첫 안내 |
| 한국 자정 뒤 숨긴 알림의 어제 증가분이 재생됨 | after Korean midnight 검사에서 (+1) 재현 | 오래된 대기 숫자는 최근 확인으로 표시. 새 값을 받으면 오늘 방문으로 전환 |
| 숨김 중 증가 후 감소를 새 증가로 알림 | decrease while hidden 검사에서 data-open=true 재현 | 마지막 표시 수와 별개로 직전 수 대비 감소를 감지해 기준과 대기 상태 초기화 |
| 60px 높이에서 오류 문구가 영역 밖으로 잘림 | short hosts 검사에서 오류 영역 경계 위반 재현 | 작은 높이용 배치/글자/패딩과 넘침 처리. 오류 위에 링크 꼬리표나 팻말을 겹치지 않음 |

## 검증 결과

- pnpm test: 81/81 통과.
- pnpm build: TypeScript 검사와 사이트/독립 ES 모듈 빌드 통과.
- pnpm test:e2e: 34/34 통과. 기존 22개에 팻말, 링크/새 탭/키보드, 선택 확인, inert HTML, 공유 요청, 취소와 늦은 응답, 화면 밖 합산, 자정/감소/0명 복구와 작은 높이 검사를 추가했다.
- 320px와 데스크톱의 실제 로컬 번들 캡처를 확인했다. 기존 모바일 터치 드래그는 스크롤을 유지하고 새 탭을 만들지 않는다. 모바일은 Chrome 에뮬레이션이며 실기기 확인은 아니다.
- 같은 문서 안에서 보이는 여러 위젯의 요청을 공유한다. 새 구독자가 기존 예약에 합류할 수 있으며 구독자마다 첫 확인까지 반드시 60초를 기다리는 계약은 아니다. 문서의 요청 간격은 활성 최소 간격을 따른다.
- 네 언어 README의 상대 링크/이미지 207개와 문서 앵커 36개, 동일 삽입 코드/명령/기술 토큰 확인.

## 실제 공개 HTML을 사용한 로컬 확인

앞서 읽은 hyunolike.tistory.com의 공개 HTML을 /tmp에서 로컬 브라우저 응답 fixture로 사용했다. 실제 홈페이지의 위젯 count=10을 새 번들이 정상 추출했고 공유 조회 1회, 외부 이미지/스크립트 요청 0건, 페이지 오류 0건이었다. 공개 블로그에 추가 조회하지 않았으며 이 검사를 반복 조회의 집계 영향이나 새 모듈의 공개 배포 검증으로 기록하지 않는다.

## 남은 외부 확인과 전달 상태

- 반복 HTML 조회가 티스토리 집계에 미치는 영향과 집계 지연, Safari/iOS 실기기는 미검증이다. 기본 조회는 끄고 소유자가 선택해서 켠다.
- 이번 구현은 티스토리의 공식 실시간 스트림이나 개별 방문자의 도착을 추적하지 않는다. 값이 없거나 범위를 벗어나면 마지막 정상 상태를 보존한다.
- 공개 배포, 실제 블로그의 새 버전 실행, 커밋과 푸시는 이번 작업에서 하지 않았다. 같은 파일 이름의 Pages 모듈을 배포하면 기존 설치에도 팻말과 링크가 보이며 선택 조회에는 속성 추가가 필요하다.
- 독립 검토가 제외한 설치 페이지 재설계 자료와 원본 블로그 스킨은 이번 기능 산출물에 포함하지 않는다.
