# 설치 페이지 전면 개편 사전 조사 — 2026-11-25

상태: 해외 서비스와 저장소 조사. 사용자 요청은 레퍼런스를 검토하고 해당 페이지의 디자인 시스템부터 전면 개편하는 것이다. 새 설계 승인/구현은 아직 진행하지 않았다. 아래 추가 기록의 화면 감사는 이번 실행에서 새로 캡처한 설치 도우미 범위다.

## 대상과 현재 맥락

주 대상은 `/install`과 `install.html`이다. 블로그 운영자가 마을을 미리 보고 설정한 뒤 올바른 설치 코드를 복사하고 티스토리 스킨에 붙여 넣도록 돕는다. 네 언어(한국어, 영어, 일본어, 중국어 간체), 오늘 방문 수 계약과 기존 픽셀 마을을 보존한다. 저장소에는 아직 커밋하지 않은 홈/사용 문서 작업이 있으며 이를 덮어쓰거나 이전 버전으로 되돌리지 않는다. 공통 디자인 규칙을 변경하면 이 두 화면에 미치는 영향도 함께 확인해야 한다.

현재 기술은 Vite 다중 HTML 진입점과 TypeScript/CSS, Custom Element/Shadow DOM/PixiJS다. `src/design-system.css`가 의미 토큰과 기본 제어를 제공하며 `src/demo.css`, `src/install.css`, `src/site-pages.css`가 각 화면을 배치한다. 프레임워크 교체를 전제로 하지 않는다.

## 디자인 시스템의 근거

- [Radix Themes Color](https://www.radix-ui.com/themes/docs/theme/color)는 배경, 인터랙션, 경계, 실색과 텍스트에 서로 다른 역할을 둔다. 이 프로젝트의 기존 의미 토큰을 기반으로 선택/오류/경고/포커스의 역할을 일관되게 정리한다. Radix 런타임 도입을 뜻하지 않는다.
- [GitHub Primer Typography](https://primer.style/product/getting-started/foundations/typography/)는 역할과 계층에 맞춘 타입 체계를 제공한다. 제목/본문/보조/코드와 네 언어 줄바꿈을 분리해 정의하고 실제 설치 화면의 정보 위계를 점검한다. GitHub UI를 복제하자는 제안이 아니다.

## 저장소에서 확인한 사실

1. `buildInstallSnippet(moduleUrl, season, refresh)`에는 블로그 주소 인자가 없다. 주소는 `normalizeBlogUrl`을 거쳐 관리자 링크와 안내 origin에 쓰인다. 주소 입력은 자동 설치/원격 연결이 아니다. 화면 표현도 이에 맞아야 한다.
2. 미리보기 24명은 고정 시연 수이며 코드에는 티스토리의 오늘 방문 수 치환자가 들어간다. 시연 인원을 실제 방문 수로 설명하지 않는다.
3. 현재 pristine/ready/dirty 상태와 비동기 복사 무효화가 구현되어 있다. 전면 개편에서도 오래된 코드/관리자 링크가 잘못 재사용되지 않도록 상태 계약을 보존하거나 명시적으로 다시 설계해야 한다.
4. 실제 위젯은 독립 번들과 Shadow DOM을 사용한다. 사이트 UI 개편을 위해 방문 수 모델/아트/외부 블로그의 링크 계약을 임의로 변경하지 않는다.
5. 다국어는 `install-i18n.ts` 메시지 사전과 URL/저장 선택/브라우저 순서로 결정된다. 새 컴포넌트와 오류/상태도 같은 번역 계약에 포함해야 한다.
6. 홈/문서는 별도 동시 작업의 미커밋 변경을 포함한다. 기존 사용자용 문서와 내비게이션을 보존하고 현재 작업과 섞어서 승인된 결정으로 간주하지 않는다.

## 시각 방향을 정하기 전에 확인할 항목

- 현재 공개 설치 화면과 로컬 홈/설치/문서의 데스크톱/모바일 캡처.
- 해외 사례 중 giscus, Tally, Typing SVG의 실제 정보 밀도와 미리보기/코드 배치.
- 대조할 안은 실제 마을을 크게 보여 주는 설정 작업실, 설치 순서 중심의 가이드, 설명과 설치를 결합한 제품 페이지다. 최종 추천/선택은 시각 근거를 확보한 뒤 정한다.
- 색상뿐 아니라 정보 구조, 컴포넌트/상태, 반응형 배치와 카피를 함께 개편한다. 마을은 실제 에셋과 렌더러를 사용하고 장식용 가짜 방문 수나 가짜 설치 완료는 만들지 않는다.

접근성 한계: 이번에는 보이는 정보 위계, 상태 표현과 작은 화면을 중심으로 확인했다. 키보드 전체 순서, 보조 기술 음성 출력, 새 팔레트 대비와 실기기는 구현 검증에서 별도로 확인해야 한다. 실제 티스토리 계정의 스킨 쓰기는 이 조사에서 수행하지 않았다.

## 비교할 시각 방향

- 마을 작업실(추천): 설정과 큰 마을을 한 작업면에 배치한다. 장점은 즉시 이해되는 시각 피드백이며 작은 화면에서는 미리보기/설정의 순서 전환이 필요하다.
- 설치 길잡이: 설정 → 코드 복사 → 스킨 붙여 넣기 순서를 중심으로 안내한다. 처음 설치하는 사람에게 명확하지만 반복 설정에는 이동이 더 필요할 수 있다.
- 미리보기 우선: 넓은 마을과 계절을 먼저 확인한 뒤 아래에서 코드를 준비한다. 제품의 개성이 강하지만 주소/코드 행동이 뒤로 밀리지 않도록 제한해야 한다.

세 방향은 기존 각진 형태, 실제 픽셀 아트, 오늘 누적 방문 수와 4개 언어, 코드/관리자 링크의 무효화 계약을 유지한다. 단순한 색상 변주가 아니라 화면의 주요 작업과 정보 구조를 비교한다. 생성 이미지에는 시안임을 명시하며 실제 구현/배포 결과로 사용하지 않는다.
