# 첨부 콘셉트 기반 픽셀 에셋 개편 검토

2026-11-25. 사용자의 평가 후 전면 수정 요청과 첨부 이미지를 선택된 아트 디렉션으로 적용했다. [개편 전 평가](pixel-assets-audit-2026-11-25.md), [명세](../spec.md), [구현 원장](../cozy-village-plan.md)을 따른다. 이 기록은 전체 EGM 다중 심사를 수행했다는 의미가 아니다.

## 평가와 변경

기존 원화는 나무와 인물의 묘사 밀도, 계절별 외형, 홍보 영상의 버전이 달랐다. 첨부의 청록 외곽과 따뜻한 크림/녹색/테라코타, 큰 픽셀 묶음을 공통 규칙으로 적용했다.

| 대상 | 반영한 변경과 확인 |
| --- | --- |
| 나무와 조형물 | 투명 PNG 나무5종과 빨간 티스토리 원/크림점5개/돌 받침을 제작했다. 서로 깊이가 있는 별도 Sprite이며 정적인 포스터를 배경으로 넣지 않았다. |
| 캐릭터 |8종의 피부/옷/외곽/바지를 따뜻한 팔레트로 수정했다.20×28px,3방향×8프레임을 유지하고 작은 화면은16×22px 전용 아틀라스를 사용한다.192프레임 전체를 확대 시트로 확인했다. |
| 집과 마을 | 크림 벽,테라코타 지붕,꽃창/차양,목재와 덤불,넓은 모래 광장으로 정리했다.7종×5계절 소품을 확인했다. |
| 효과와 게스트 | 산타/루돌프,말풍선3종,눈/꽃잎/단풍과 트리 빛을 같은 팔레트와 각진 묶음으로 정돈했다. 루돌프 몸과 다리의 두 자세도 구분했다. |
| 화면과 미디어 |5계절/데스크톱/320·375px를 재캡처하고 README4개 언어의 갤러리와 출처를 갱신했다. 병행 제작한 실제 PixiJS 소개 영상/포스터/GIF의 새 원화를 확인해 보존했다. |

포스터의 제목과 흰 둥근 프레임은 제품 그림에 굽지 않았다. 원본은5명의 연출 장면이고 실제 위젯은 입력한 오늘 방문자 수만큼 걷는 마을이다. 같은 위치의 착석 포즈나 구도 복제를 완료했다고 주장하지 않는다.0~5000명과 기본Christmas,현재 인원/ID,계절 전환/일시정지/모션 줄이기,4개 언어/설치 코드 계약을 유지했다.

## 원화 출처와 실행 파일

[제작 기록](../../../../assets/concepts/cozy/README.md)에 전체 프롬프트와 생성 원본6개를 보존했다. 사용자가 준 이미지 외의 게임 에셋을 가져오지 않았다. 생성 원본은 모두1254×1254 RGBA이며 실제 실행 파일은 원본 전체를 Canvas nearest로180×180에 렌더한 PNG다.6개 합계208,003bytes. [실행 파일 해시](../../../../assets/concepts/cozy/exports.json)를 남겼다.

캐릭터/집/소품/효과는 기존 편집 가능한 RGBA/Canvas 원본을 직접 편집했다. 생성 원화에는 미세한 색 변화와 저알파 가장자리가 있어 수작업의 엄격한 단일 도트 격자와 동일하다고 설명하지 않는다. 실제 표시 크기에서 외곽과 계절 식별을 확인했다. 티스토리 표장은 해당 서비스의 브랜드다.

## 독립 검토와 한 번의 수정

cozy_readiness가 구현 준비를 별도 문맥에서 점검했다. cozy_final_review가 최종 코드/원화 메타데이터와 모델/불투명 픽셀 경계를 점검했다. 최종 검토 결과 치명0,중요1,경미2건이었다. 검토자는 전체 브라우저 검사나 실제 티스토리 스킨을 실행하지 않았으며,아래 재검증은 구현 담당이 수행했다.

| 수준 | 발견과 수정 |
| --- | --- |
| 중요 |128×100/156×100 논리 화면에서 캐릭터 중심만 제한해 가장자리 픽셀이 잘렸다. 전체 프레임의 반폭/높이로 표시 좌표를 보정하고 아주 작은 호스트에서는 축소한다. 모델의 인원/이동 값은 보존하며 말풍선도 보정된 발 위치를 따른다. 새8개 단위 검사와 실제320/375px/5000명 Sprite bounds 검사로 실패를 재현하고 수정 후 통과했다. |
| 경미 | 조형물 실패도Christmas의 tree오류로만 알렸다. monument/tree를 구분하고 현재 계절에서도 선택 언어로 village-error를 전달한다. 기존 실패/재시도 검사에 종류와 일본어 메시지 검증을 추가해 통과했다. |
| 경미 | 조형물 원본을1280×1280으로 기록했으나 실제1254×1254였다. 보존된 원본에 맞춰 문서를 정정했다. |

구현 중 이미지 실패 경고가 정상 계절에도 남는 문제와 공유 Texture 파괴로 다른 위젯이 손상되는 문제도 실제 Chrome에서 재현했다. 현재 계절별 경고와 인스턴스별 Canvas/Texture 소유권으로 해결했다. 실패 요청을 영구 캐시하지 않고 초기화가 취소된 인스턴스를 늦게 부착하지 않는다. 조형물 받침 장애물 영역과 생성 위치도 의미 있는 모델 검사로 확인했다.

## 소개 영상 확인과 공유 작업 보존

별도 소개 영상 작업이 같은 공간에서 실제 PixiJS Web Component와 설치 작업실을 캡처해 갱신한 파일을 검증했다. 자체 Canvas2D 초안은 최종 산출물로 채택하지 않았고 다른 작업의 README/구조도/미디어/제작 스크립트를 보존했다. [제작 기록과 음원 크레딧](../intro-media.md)을 따른다.

ffprobe로20.000초/1920×1080/H.264/30fps/600프레임,AAC/48kHz/stereo,3,813,186bytes를 확인했다.0.3/6.5/10/14.5/19초를 디코딩해 새 원화/조형물,게스트,계절과 설치 화면을 직접 열었다. 포스터186,912bytes,GIF1,614,839bytes다. MP4 SHA-256:`ea8ad2160695af4ddde7ef23b15276db6a5f47d931832c6a157df4ff73f34f0b`.

촬영 당시 모듈SHA는 intro-media.md에 보존한다. 이후 좌표/진단 수정으로 현재 모듈 바이트가 달라졌으므로 영상이 최신 모듈과 해시까지 같다고 주장하지 않는다. 영상에 사용하는 원화는 이번 개편과 같다.

## 전달 상태

로컬 구현/검증을 마쳤고 [미리보기](http://127.0.0.1:5201/install.html?lang=ko)를 제공한다. 최종 필수 수정은 남아 있지 않다. 새 커밋/푸시/공개 배포와 실제 티스토리 스킨 설치는 수행하지 않았다. 모바일은 에뮬레이션이며 실기기/보조기기 검증은 아니다. 인원을 줄이지 않으므로 좁은 화면이나 높은 인원에서 밀집/겹침이 생기는 정책은 유지한다.
