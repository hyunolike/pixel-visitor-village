# 방문 수 팻말과 저장소 링크 구현 계획

> 실행: 이 세션에서 직접 구현하고 마지막에 새 문맥의 독립 검토를 받는다. 사용자 진행 승인 범위에서 실행하며 별도 커밋, 푸시와 공개 배포는 포함하지 않는다.

**목표:** 마을 안의 작은 나무 팻말로 오늘 방문 수와 증가분을 알리고, 마을 클릭으로 저장소를 연다.

**구조:** PixiJS Canvas 위에 Shadow DOM의 HTML 팻말과 실제 링크를 둔다. 방문 수 변화 계산과 주기 조회의 수명 관리는 별도 TypeScript 모듈로 분리한다. 외부 에셋이나 의존성은 추가하지 않는다.

**명세:** [요구사항](spec.md)의 VV-019~021 및 [설계](design.md)의 방문 수 알림 절.

**기준:** 24010fc, 작업 트리 깨끗함. 기존 linked worktree의 feat/visitor-notice에서 진행한다.

## 확정 범위와 경계

- 첫 표시에는 오늘 방문 수만 알리고, 같은 한국 날짜의 증가에만 +차이를 표시한다. 동일 값과 감소는 증가 알림을 만들지 않는다.
- 최초 알림과 증가 알림은 마을이 보일 때 시작한다. 숨김/화면 밖에서는 타이머도 멈추며 복귀 시 최신 값 한 건만 알린다.
- 팻말은 오른쪽 위에서 약 300ms 내려오고 3초 표시한 뒤 올라간다. 모션 줄이기에서는 이동/페이드 전환을 없앤다. 좁은 호스트는 팻말 표시 동안 계절 이름을 숨긴다.
- 전체 마을에 저장소의 실제 a 링크를 둔다. 새 탭, noopener noreferrer, 목적지와 새 탭 안내, 키보드 포커스, 모바일 스크롤을 지원한다. 링크의 보이는 꼬리표는 오른쪽 아래에 둔다.
- 조회는 refresh-interval 속성으로 명시적으로 켠다. 기본 0(끄기), 허용 0 또는 60~3600의 정수 초. 잘못된 설정은 오류를 알리고 마지막 정상 설정을 유지한다. 기존 설치에 자동 네트워크 요청을 추가하지 않는다.
- 조회 대상은 현재 origin의 루트 HTML 한 곳이다. redirect:error, credentials:omit, cache:no-store와 10초 제한을 적용한다. DOM의 inert template에서 visitor-village[count]를 읽으며 외부 스크립트/이미지를 실행하거나 요청하지 않는다. 비어 있거나 잘못된 치환자는 오류다.
- 동일 호스트의 복수 위젯은 하나의 조회기를 공유한다. 보이는 구독자가 없으면 요청과 타이머를 중지한다. 마지막 구독 해제는 요청을 취소하며 늦은 응답은 무시한다.
- 최초 조회는 60초 이상 뒤에 한다. 성공 후 설정 간격, 실패 후 최대 15분까지 지수 백오프한다. 페이지 숨김과 화면 밖에서는 요청을 중단하고 복귀 후에도 최소 설정 간격을 기다린다. 중첩 요청은 금지한다.
- 네트워크 오류, HTTP 오류, 비 HTML 응답, 잘못된 수와 5,000 초과는 마지막 정상 마을을 보존하고 village-error(attribute:refresh)를 알린다. 성공 시 관련 안내를 지운다.
- 사용자 블로그에서 Today:10과 count=10인 공개 HTML을 확인했다. 실제 브라우저의 집계 지연과 반복 조회의 집계 영향은 미검증이다. 자동 조회는 선택 기능으로 제공하고 티스토리 공식 실시간 기능으로 설명하지 않는다.
- 설치 도우미와 네 언어 README에 선택 속성과 이 경계를 설명한다. 정적 삽입 예제는 기본적으로 조회를 끄고 선택 방법을 주석으로 안내한다.

## 독립 사전 검토 후 확정한 세부 계약

- 활성 구독자의 최소 간격으로 한 번 조회하고, 시작 시점부터 계속 활성인 동일 구독 세대에만 전달한다. 간격 최솟값이 바뀔 때만 예약을 재설정한다. 실패마다 2배로 늘리되 설정 간격과 15분 중 큰 값을 상한으로 하고, 성공 시 실패 횟수를 0으로 만든다.
- 요청 시작 후 외부 count 변경 또는 구독 활성 상태 변경은 해당 구독 버전을 올린다. 공유 요청은 유지해도 그 응답을 버전이 바뀐 구독자에 적용하지 않는다.
- HTML의 모든 visitor-village[count]를 검증하고 한 개 이상이며 모두 같은 정상 값일 때만 사용한다. 빈 값, 미치환 값과 서로 다른 수는 오류다. 외부 자원 로드 방지는 inert template로 검증한다.
- 오류 안내와 별개의 aria-live=polite, aria-atomic=true 팻말을 쓴다. 마지막 표시한 한국 날짜/수를 증가 기준으로 하고 숨김 중 최신 값까지 합산한다. 감소는 기준을 재설정하며 낡은 대기 알림을 지운다. 새로 받은 값의 날짜 변경은 증가 없이 오늘 수만 표시한다. 어제 저장한 대기 알림을 오늘 다시 보여줄 때는 현재 수로 위장하지 않고 최근 확인으로 표시하며, 새 값을 받으면 오늘 방문으로 복구한다. 표시 도중 숨기면 복귀 시 최신 한 건을 3초간 다시 표시한다.

## 검토 초점

- 화면 밖에서 취소된 요청의 늦은 완료가 count를 덮어쓰지 않는가.
- 복수 위젯과 반복 연결이 요청 수를 늘리지 않는가.
- 타임아웃과 동일 origin 리다이렉트도 정해진 실패 처리로 돌아오는가.
- 실제 링크가 터치 스크롤을 클릭으로 오인하거나 오류 안내를 가리지 않는가.
- 첫 값/한국 자정/감소를 새 방문으로 오인하지 않는가.

## 진행 기록

- 계획 준비: 구현/배포/커밋 전. 집계 영향 미검증으로 조회를 명시적 선택 기능으로 확정했다.

- 완료 검증: 단위 81/81, 타입/빌드 통과, 브라우저 34/34. 독립 사전/구현 검토를 실제 수행했고 중요 결함 네 건은 실패 재현 후 수정했다. 별도 EGM 반복 검토 수렴으로 주장하지 않는다.
- 구현 판단: 반복 조회 영향 미검증 때문에 조회는 기본 끄기/명시적 선택으로 유지한다. 자정을 넘긴 저장 알림은 최근 확인으로 표시해 오늘 숫자로 오인하지 않게 했다.
- 동시 작업 보존: 문서 상단의 설치 도우미 재설계 초안과 해당 제안 PNG/검토 자료는 이번 변경의 검토/수정 범위에서 제외했다.
